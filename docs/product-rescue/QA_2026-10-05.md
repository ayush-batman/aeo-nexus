## 1. Summary

**Verdict:** the code base is in good shape at the gate level (lint, app type-check, 361 tests and the production build all pass) and the measurement trust boundary largely holds: failed providers produce errors rather than invented data, prose-only links are labelled `link_mentioned`, quota and tenant isolation are enforced server-side. The most important problems are measurement *accuracy* issues that the existing tests do not catch, an idempotency bug in `/api/v1/scan`, and a billing gap for Razorpay.

**Top 5 issues**

1. **High — common-word brands produce false mentions.** "Buffer", "Notion", "Slack", "Later", "Monday" are matched case-insensitively in ordinary prose ("a buffer of time", "schedule it later"). The homepage's own example brand is "Notion". (M-1)
2. **High — Razorpay purchases never expire.** A one-time Razorpay payment for a "per month" plan upgrades the organization with no expiry or renewal path. (B-1)
3. **Medium — `/api/v1/scan` retries with the same `Idempotency-Key` get 409, not the original run.** Clients and the MCP server cannot safely retry after a timeout. (A-1)
4. **Medium — `/api/free-scan` reports a 0 % / 100 % "visibility" from one branded answer**, and a model saying "I don't know Zylqor" counts as a mention → 100 %. (M-3)
5. **Medium — header navigation has no visible keyboard focus indicator; several mobile targets are under 44 px.** (U-1, U-2)

## 3. Findings

Severity: Critical = trust boundary, data leak, authz · High = wrong measurement or broken core/billing journey · Medium · Low. "Verified" = reproduced by running code; "Code-verified" = confirmed by reading code, not executed; "Suspected" = plausible, needs confirmation.

### Measurement

**M-1 High — false brand mentions for common-word brand names. Verified.**
`lib/ai/brand-matching.ts` `findNamePositions` matches aliases case-insensitively at word boundaries with an optional plural/possessive suffix.
Repro (`npx tsx`, `findBrandMentions(text, brand)`):

| Brand | Text | Result |
|---|---|---|
| Buffer | "You need a buffer of time between posts." | mentioned |
| Notion | "The notion of a single workspace is appealing." | mentioned |
| Slack | "There is some slack in the budget." | mentioned |
| Later | "You can schedule it later." | mentioned |
| Monday | "Post on Monday for best reach." | mentioned |
| Buffer | "Buffers are useful." | mentioned |

Expected: a brand that is also a common word needs case-sensitive or contextual matching (as short aliases already do). Actual: inflated mention rate, which is the headline metric. Competitor counts (`competitorsMentioned`) use the same matcher — "Later" is a real competitor in the Buffer QA data.

**M-2 Medium — list position counts non-list lines. Verified.**
`parseListItems` in `lib/ai/ai-analyzer.ts` treats any line starting with digits and `.`, `)` or `:` as a list item. Response `"2026: the year of AI.\n\n1. Hootsuite\n2. Buffer\n3. Later"` gives Buffer `mentionPosition` 3 instead of 2. Bold-name answers (`**Buffer**: …`) are parsed as bullets with a leading `*` left in the item.

**M-3 Medium — `/api/free-scan` presents a one-sample 0/100 % "visibility". Code-verified + matcher verified.**
`convex/discoveryActions.ts` `freeScan` asks "What is {brand}?" and returns `visibilityScore: brandMentioned ? 100 : 0` from one answer. Because the brand name is in the question, an answer like "I don't have reliable information about Zylqor" is a mention (verified with `findBrandMentions`) → 100 %. The response does carry `samples: 1` and a note. The UI that renders it (`components/landing/try-free-section.tsx`) is not imported anywhere, but the endpoint is public. Contradicts the measurement rule against single-sample scores.

**M-4 Low — battle-mode reason text claims what wasn't measured. Code-verified.**
`lib/ai/llm-scanner.ts`: when positions tie and the brand's sentiment < −0.2, `winnerReason` says "{competitor} received more positive sentiment", but competitor sentiment is never analysed (always `'neutral'`).

**M-5 Low — brand matching has no accent folding.** "Café" does not match "Cafe". Verified.

**M-6 Info — Claude adapter timeout may be too short. Suspected.** Claude runs with web search (`max_uses: 3`) under the same 20 s timeout as Gemini; failures surface honestly as `provider_timeout`, but the Claude failure rate may be high. Needs a live measurement.

**Held (no finding):** all-engines-failed returns empty results with real errors, no mock fallback; `google_ai_overview` and `mock` throw `unsupported_engine`; prose URLs are `link_mentioned`, provider references `provider_citation`, unresolved Gemini redirects `unverified`; private/loopback citation hosts are marked `blocked`; Wilson interval returns `level: 'none'` at n = 0; comparisons require ≥ 4 samples per cohort.

### API and authorization

**A-1 Medium — `/api/v1/scan` idempotent retries return 409. Verified (convex-test).**
`convex/apiWrites.ts` `beginScan` throws `request_id_conflict` whenever a run with the same `requestId` exists, before reaching `beginMeasurement`, which already handles an identical retry by returning the existing run. Probe: two identical `beginScan` calls → first returns a run id, second throws `request_id_conflict` (HTTP 409 `duplicate_scan_request`). Expected: same run id. Impact: a client that times out at the 230 s poll deadline cannot recover its run by retrying.

**A-2 Low — `no_engines_available` maps to 503 "temporarily unavailable — retry".** It is a configuration state; retrying will not help (`lib/api-v1.ts`, `lib/convex/http.ts`).

**A-3 Low — public-scan id validation accepts 36 hyphens. Verified.** `/^[a-f0-9-]{36}$/i` in `app/api/scan/public/route.ts` and `convex/publicScans.ts`; `reserve` accepted `"------------------------------------"` and created a scan.

**A-4 Low — `invalid_public_scan` is not mapped in `convexRouteError` (→ 503).** The route now pre-validates the same rules, so it is latent; the 26 Sept report saw it as a live 503.

**A-5 Info — client IP is taken from the first `X-Forwarded-For` value** (public scan, brand enrich, free scan, prompt discovery). Safe on Vercel, which overwrites the header; spoofable behind any other proxy, bypassing the per-IP quotas.

**A-6 Low — SafeFetch does not block the NAT64 prefix `64:ff9b::/96` or 6to4 `2002::/16`.** Only exploitable where the runtime network has NAT64. `lib/security/safe-fetch.ts`.

**Held:** missing key → 401, missing scope → 403, rate limit → 429 with `Retry-After` (`lib/api-v1.ts`, existing tests); free plan capped at 3 runs per rolling 7 days — 4th `measurements.begin` → `scan_quota_exceeded` (verified); free plan requesting ChatGPT → `engine_not_entitled` (verified); measurement in a foreign workspace → `workspace_not_found` (verified); public scan IP quota 3/7 days — 4th → `rate_limit_exceeded` (verified); dev auth bypass ignored by the production build — `/dashboard`, `/onboarding`, `/admin` with `dev-auth-bypass=true` redirect to `/login` (verified); a forged session cookie renders the dashboard shell (200) and `/admin` redirects to `/dashboard` — by design the proxy is a navigation hint and data is checked in Convex (not verifiable without a backend); cron routes use constant-time secret comparison; SafeFetch pins resolved IPs, re-checks every redirect, blocks private ranges, credentials and non-standard ports.

### Billing

**B-1 High — Razorpay one-time payment grants a monthly plan indefinitely. Code-verified.**
`convex/billingActions.ts` `applyRazorpay` → `billing.applyVerifiedEvent` sets `organization.plan` from a captured one-time order. Plans are priced "per month" (`lib/billing/plan-catalog.ts`), but there is no expiry, renewal or downgrade path for Razorpay anywhere in `convex/` or `lib/billing/` (no expiry field in the schema). Needs a product decision (Razorpay Subscriptions, or an expiry date plus a downgrade job).

**Held:** Stripe and Razorpay webhooks reject missing/invalid signatures (400) and missing secrets (503, no mutation); events are deduplicated by provider event id; stale/out-of-order events are recorded but not applied; plan comes from a server-side price/amount/currency mapping; checkout `org_id` must match subscription metadata.
